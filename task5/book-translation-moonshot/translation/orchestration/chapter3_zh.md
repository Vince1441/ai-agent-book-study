# 第 3 章：优化推理时延

模型能够正常工作之后，下一场硬仗就是速度。我们的目标是在降低**时延**的同时提升**吞吐量**——即系统每秒能够完成的请求数量。这两者往往相互制约、此消彼长。

最重要的技巧是**键值缓存**。在推理过程中，如果不加缓存，模型每生成一个新词元，都要对之前所有词元重新计算一次注意力机制。通过缓存历史词元的键向量和值向量，模型只需处理最新的词元，这能在处理长提示词时大幅降低时延。

```python
def decode_step(new_token, kv_cache):
    q, k, v = project(new_token)         # only the new token
    kv_cache.append(k, v)                # reuse past keys and values
    return attention(q, kv_cache.keys, kv_cache.values)
```

第二个技巧是**批处理**[待审]：将多个提示词组合在一起，让硬件保持忙碌。更大的批次能提升吞吐量，但可能损害单个请求的时延，因此服务系统需要精心调节批次大小。

其中的要点在于，推理性能是一种平衡艺术。每一个我们避免重复计算的词元，以及每一组我们妥善批处理的提示词，都在推动系统同时迈向更低的时延和更高的吞吐量。
