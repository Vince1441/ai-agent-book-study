# Task 1

## 学习任务:
1. 理解上下文工程（Context Engineering）的基本概念
   Agent的"眼睛",Agent只能根据其所能看到的信息进行决策,也就意味着Agent的上下文越完整,越规范,Agen的能力就越强;而对上下文的设计,管理工作称为上下文工程.

2. 理解 Prompt 与 Context 的区别 了解 Context Window 与 Token 限制
   Prompt(提示词)指的是与大模型的对话文本中设置角色.目标.规则等限制去指导模型如何做.做什么,核心是如何把指令写清楚;
   Context(上下文):提供给模型进行本次决策所需的整体前置信息,包括指令,会话历史,工具,状态等,核心是模型做出决策前,需要看到什么;

   Context Window(上下文窗口):模型一次处理过程中能够容纳的上下文规模，通常使用 Token 作为计量单位。

4. 学习上下文的选择、组织与管理;了解长上下文、上下文压缩等基本思路
   - 上下文的选择:根据任务的意图,辨析完成任务所需条件,只提供完成任务所需要的信息;
   核心思路:先提供能力目录,需要某项工具时,再加载相应的详细信息.

   - 上下文的组织:静态前缀(系统提示词+核心工具定义)+动态轨迹(当前任务状态,工具返回结果,用户信息等);亦可概括为:稳定的信息放前面,不断变化的信息放后面;
   
   - 上下文的管理:Agent状态栏,把 Agent 需要反复从历史中推断的运行状态，提前计算成一份清晰的状态摘要。大量的 token 中只包含少量关键的状态信息。Agent 状态栏主动提取这些关键状态，以极低的额外 token成本，呈现出原本需要扫描数千个 token 才能获得的信息。

   - 上下文压缩:把冗长历史提炼为更短、更有价值的内容，同时尽量保留后续决策所需的事实。

5. 理解为什么上下文工程是 Agent 能力的重要组成部分
   首先需要清楚的一点:Agent有别于普通聊天模型,普通聊天模型只需要完成一次回答问题即可,而Agent一般需要完成一系列行动; 
   然后,Agent下一步要做什么,取决于它目前掌握的上下文,而不单单是用户最初的那条指令,上下文工程影响的是 Agent 的决策依据、连续性、执行效率和可控性。

   - 根据API 消息结构、稳定前缀、Prompt、Skills、Agent 状态栏和上下文压缩等内容进行对上下文的组织.管理.压缩;这些机制组合起来，构成了一套为 Agent 持续供给有效信息的工程体系。
