# Task 2 -- 用户记忆和记忆库

## 综合概述
- 用户记忆：针对单个用户的个性化记忆--Agent在与用户的不断交互中，逐渐了解其使用偏好、习惯和需求，构建专属于该用户的知识模型；
- 短期记忆：根据聊天记录/轨迹生成的当前上下文，参与模型推理
- 长期记忆：筛选相关的信息，并存入长期记忆库；需要用到时，将此信息从记忆库中检索出来，加入当前上下文，参与本次推理。




## 自测问题
1. 聊天记录、当前上下文和长期用户记忆，是同一回事吗？
- 不是同一回事，
  聊天记录：历史会话事件原始记录;
  当前上下文：当前推理请求实际获得的信息；
  长期记忆：跨会话的持久化知识，经过筛选、提炼、核验并持久化的信息事实；


2. 用户先说“我住在北京”，后来又说“我搬到了上海”，你会怎样保存和使用这两条信息？
- 保存：首先，识别确认两条信息的主体均为“我”；“住在北京”➡️“搬到了上海”表达了明确的状态改变，故可保存为：
{
  "current_city": "上海",
  "historical_cities": ["北京"],
  "change_event": "用户表示已从北京搬到上海",
  "source": "用户直接陈述"
}
- 使用：查询“我现在住在哪里”时，回答上海；查询“我曾经住在哪里“时，利用聊天记录历史事件回答北京。
- 注意：如果两条信息存在不明确的时间条件或对象差异，应核验原始资料，必要时询问用户。


3. “记住用户偏好”和“查询产品说明书”分别更侧重什么能力？两者能否使用相同的检索技术？
- ”记住用户偏好“更侧重长期记忆管理；
- ”查询产品说明书“更侧重RAG（检索增强生成）
- 二者可共享Embedding、重排序、混合检索技术；


4. 文档块切得太大或太小，分别可能带来什么问题？
- 文档块切得太大：容易造成多个主体内容混淆在一起，造成向量语义稀释、检索结果不正确等问题；
- 文档块切得太小：会丢失上下文，实体指代、事件条件；
- 应根据任务、文档结构、模型输入限制等条件进行文档分块（Chunking）

5. RAG 回答错了，你会怎样区分：没有检索到证据、检索到了错误证据，还是模型没有正确使用证据？
- 没有检索到证据：正确文档内容不在初始候选集合中，优先改进文档切块、Embedding；
- 检索到了错误证据：候选集合混入了错误版本、主体对象或时间条件重合，需改进重排序、来源质量；
- 模型没有正确使用证据：Prompt可能出错，需改进Prompt、证据引用、生成约束。
